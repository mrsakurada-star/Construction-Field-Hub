# Service Book 設計プラン

> 作成日: 2026-06-02 / Construction Field Hub 新ツール「サービス報告書・点検履歴台帳」
> © 2026 Nozomi Sakurada. All rights reserved.

## 1. 概要

給湯機器の点検・サービス履歴を **「顧客 ＞ 設置機器 ＞ サービス記録」** の3階層で蓄積する台帳ツール。
データは `data/` フォルダの JSON を Directory Access API で自動同期する（BtoB価格表ツールと同方式）。

- **主成果物**: **A4依頼票（作業指示票）** と **A4サービス報告書**（点検/修理単票）の2種
- **保存方式**: IndexedDB を主ストアにしつつ `data/` フォルダの JSON へ自動同期
- **動作環境**: ブラウザ完結（推奨 Chrome / Edge 最新版）

履歴はデータとして蓄積するが、印刷物は「1訪問＝1記録」の単票A4を発行する設計とする。

## 2. データモデル

IndexedDB のストア構成（`data/` 配下の JSON と1対1で同期）。

### customers（顧客）
| フィールド | 内容 |
|---|---|
| id | 主キー（autoIncrement） |
| name | 顧客名 |
| kana | フリガナ（全角カナ正規化） |
| contact | 担当者名・TEL |
| address | 住所 |
| dealerName | 依頼元 / 販売店名 |
| houseMaker | ハウスメーカー |
| printNote | 特記事項（**報告書に印刷される**） |
| memo | 備考（**印刷非表示・社内用**） |

### equipments（設置機器）
| フィールド | 内容 |
|---|---|
| id | 主キー（autoIncrement） |
| customerId | 顧客への外部キー |
| maker | メーカー（パーパス / ノーリツ / リンナイ / パロマ 等） |
| modelNo | 型式 |
| lotNo | 製品ロット / 製造番号 |
| category | 機器区分（給湯器 / 風呂釜 / レンジフード 等） |
| gasType | ガス種別 |
| installDate | 設置日 |
| **usage** | **用途（例: 浴室給湯・厨房給湯・暖房 など）** |
| memo | 備考 |

### serviceRecords（サービス記録 ＝ 報告書1件）
| フィールド | 内容 |
|---|---|
| id | 主キー（autoIncrement） |
| equipmentId | 設置機器への外部キー |
| mgmtNo | 管理番号（依頼発行時に自動採番） |
| receivedDate | 受付日（依頼発行日） |
| receptionist | 受付者 |
| requestedDate | 希望日（お客様希望の対応日） |
| serviceDate | 対応日 |
| completionDate | 完了日 |
| staff | 担当者 |
| callContent | コール内容（受付時のお客様からの依頼/申告内容） |
| workType | 作業種別（定期点検 / 故障修理 / アラーム対応 / 設置） |
| parts[] | 交換部品 `{ name, qty, unitPrice }` の配列 |
| fee | 料金 `{ visitFee(出張料), laborFee(技術料), partsFee(部品代), total(合計) }` |
| remarks | 担当者所見 |
| customerReport | お客様への報告 |
| status | 進行状況（`open`=進行中 / `completed`=完了） |
| createdAt | 作成日時（ISO文字列） |
| updatedAt | 最終更新日時（ISO文字列・放置検知に使用） |

> `completionDate` が入力され `status` が `completed` になると完了扱い。`open` のまま `updatedAt` が古いものを「放置案件」として検知する（§5 参照）。

### appSettings
フォルダハンドル等の永続化（BtoBと同じ）。

## 3. 画面構成（タブ型 / A案・BtoB踏襲）

1. **新規依頼発行** — 受付（コール）を起点に新しい依頼を起こす入口。顧客・機器を選択（または新規登録）し、受付情報・コール内容を入力 → 未完了（`open`）のサービス記録を生成し、**依頼票（作業指示票）をA4印刷**できる。
   - **過去履歴からコピー発行**: 過去のサービス記録を選んで新規依頼として複製できる。引き継ぐのは **機器（＝紐づく顧客・依頼元・住所・ハウスメーカーも自動的に同伴）と作業種別**。管理番号・受付日は新規（今日）で採番し、対応日/完了日/担当者/所見/コール内容/交換部品/料金はクリアして `open` で起票する。リピート顧客の再訪で再入力を省ける。
2. **顧客管理** — 顧客の登録/編集、依頼元情報。一覧から機器へドリルダウン。
3. **機器管理** — 顧客に紐づく機器カード（型式・ロット・用途・設置日）。一覧から記録へ。
4. **サービス記録** — 機器を選び、点検/修理の記録を追加・編集。過去履歴を時系列表示。完了化（`completed`）もここで行う。
5. **報告書印刷** — 選択した1記録をA4プレビュー → 印刷 / PDF。

> 業務フロー: **新規依頼発行**（依頼票発行）→ 現場対応 → **サービス記録**で補完・完了化 → **報告書印刷**。発行直後〜完了までは `open` 状態で、放置されると §5 の警告対象になる。

## 4. 検索・入力正規化（横断あいまい検索）

表記ゆれを吸収し検索ヒット率を上げるための、独立したユーティリティとして実装する。

### 4.1 横断あいまい検索
- **検索対象**: 顧客名・住所・連絡先・機種（型式）を横断するインクリメンタル検索
- 入力に応じてリアルタイムで候補を絞り込む

### 4.2 正規化ロジック（保存時・検索時の両方に適用）
- 英数字・記号 → **半角に統一**
- カタカナ → **全角に統一**
- 大文字小文字を無視
- 空白・ハイフン（－ / - / ー）のゆれを吸収
- 例: 「ＧＨＨ２４００」「ghh-2400」「GHH 2400」がすべて同じ機種にヒット

### 4.3 入力ガード（半角全角の自動変換）
- **方式: 自動変換**（ユーザーは意識せず表記が揃う）
- 型式・電話番号・製品ロット等 → 全角入力を検知したら**自動で半角変換**
- フリガナ等 → **全角カナに統一**
- 入力 / 保存のタイミングで `normalize()` を適用し、データを常に正規化済みで保持する

## 5. 放置案件の警告（更新停滞検知）

未完了のまま放置されているサービス記録を検知し、警告表示する。フォローアップ漏れを防ぐ。

- **判定対象**: `status` が `open`（完了日未入力）のサービス記録
- **判定条件**: `updatedAt`（最終更新日時）から **14日（2週間）以上経過**
- **見せ方**（BtoB価格表の期限切れ警告と同じ流儀）:
  - 各タブ上部・サービス記録一覧に「放置案件 N件」のバッジを表示
  - 該当行を**赤系で強調**（経過14日以上＝赤、間近の警告帯を設ける場合は7日以上＝オレンジ等）
  - 経過日数を表示（例: 「最終更新から18日」）
- **更新の定義**: 記録の追加・編集で `updatedAt` を現在時刻に更新。完了（`completed` 化）した記録は対象外。
- 閾値（14日）は実装時に定数化し、後から調整可能にする。

## 7. 出力レイアウト（A4縦・各1枚）

出力は **依頼票** と **サービス報告書** の2種。どちらも同じ記録（serviceRecords）から生成する。

### 7.1 依頼票（作業指示票）— 新規依頼発行時

| 区画 | 内容 |
|---|---|
| ヘッダー | タイトル「作業依頼票」＋管理番号＋受付日 |
| 受付情報 | 受付者・希望日・作業種別 |
| 依頼元情報 | 依頼元 / 販売店名 |
| お客様情報 | 顧客名・住所・TEL・担当・ハウスメーカー |
| 特記事項 | 顧客の `printNote` |
| 機種情報 | メーカー・型式・製品ロット・用途 |
| コール内容 | 受付時のお客様からの依頼/申告内容 |
| 現場記入欄 | 対応日・担当者・作業内容（手書き用の空欄） |
| フッター | 会社名 / コピーライト |

### 7.2 サービス報告書 — 対応完了時

| 区画 | 内容 |
|---|---|
| ヘッダー | タイトル「サービス報告書」＋管理番号＋対応日 / 完了日 |
| 依頼元情報 | 依頼元 / 販売店名 |
| お客様情報 | 顧客名・住所・TEL・担当・ハウスメーカー |
| 特記事項 | 顧客の `printNote`（印刷対応の特記事項） |
| 機種情報 | メーカー・型式・製品ロット・**用途** |
| コール内容 | 受付時のお客様からの依頼/申告内容 |
| 作業内容 | 作業種別・担当者所見・お客様への報告 |
| 交換部品テーブル | 品名・数量・単価・金額 |
| 料金明細 | 出張料・技術料・部品代・合計 |
| フッター | 会社名 / お客様確認サイン欄 / コピーライト |

- 印刷時は操作ボタンを非表示にし、A4縦1枚に収める（既存ツールの印刷最適化を踏襲）。
- 顧客の `memo`（備考）は**社内用のため報告書には出力しない**。`printNote`（特記事項）のみ印刷される。
