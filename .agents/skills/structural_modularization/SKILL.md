# `structural_modularization` スキル

このスキルは、1つのファイルに全コードが記述された「モノリシックなHTMLファイル」を、安全に改修・拡張できるよう、機能ごとにファイルを分割・構造化する際のガイドラインです。

## 1. 原則 (Core Principles)

* **関心の分離 (Separation of Concerns)**:
  * **HTML (`index.html`)**: UIの骨組み、外部ファイルの読込のみを担当。インラインスタイルや巨大なスクリプトは記述しない。
  * **CSS (`css/style.css`)**: 画面デザインおよびA4印刷レイアウト（`@media print` 等）を担当。
  * **JavaScript (`js/*.js`)**: データと処理ロジックを担当。機能単位（例：保存、印刷、計算）で細かくファイルを分ける。
* **レガシーの保護 (Legacy Protection)**: リファクタリングによって動作が壊れた場合に備え、必ず元のファイルを `legacy/` フォルダへ移動・退避する。

## 2. 標準的なフォルダ構造

ツールを分離する際は、以下の構造を基本とします。

```text
[Tool Name]/
  ├── index.html        (UIの土台。中身は最小限にする)
  ├── css/
  │    └── style.css    (全体のスタイルや印刷レイアウト設定)
  ├── js/
  │    ├── data.js      (初期データ、設定値、定数リストなど)
  │    ├── logic*.js    (計算、出力、表示切り替えなどの機能別ファイル群)
  │    └── app.js       (初期化処理、機能統合、DOMとの紐付け)
  └── legacy/
       └── [original_tool_name].html (元の旧ファイルをそのまま保管)
```

## 3. 実装のステップ

1. **バックアップ作成**: 対象フォルダ内に `legacy` フォルダを作り、既存のHTMLファイルを移動（またはコピー）する。
2. **フォルダ生成**: `css`、`js` フォルダを新規作成する。
3. **CSSの抽出**: `legacy/` に移動したHTML内の `<style>` タグの内容を全て抽出し、`css/style.css` へ保存する。
4. **JS機能の分割抽出**:
   * 固定のデータセットやチェックリスト定義があれば `js/data.js` へ抽出する。
   * 主要なロジックを関数グループごとに `js/xxx.js` へ抽出する。（例：`storage.js`, `pdf_export.js`）
   * 画面の初期描画やイベントリスナー（`DOMContentLoaded` 等）を `js/app.js` へまとめる。
5. **`index.html` の再構築**:
   * 新しく作成した `css/style.css` や `js/*.js` を適切な順番で読み込むよう `<head>` や `<body>` 末尾にタグを記述する。
   * 元のHTMLから `<style>` と `<script>` ブロックを取り除いたクリーンなHTML骨組みだけを残す。
6. **動作確認**: ロジックが正常に接続されているか、データの保存・出力などは元通り動くか確認する。

## 4. 適用時の注意点

* **変数のグローバル参照**: 複数のJSファイルに分割した際、変数が他のファイルから参照できるか（スコープ）に気をつける。必要に応じて `window.変数名` を使うか、1つの設定オブジェクトにまとめる。
* **Lucideアイコンの適用**: リファクタリングの機会に、デザインの統一を図るため、旧来の絵文字（📄や🔧など）や他ライブラリのアイコンを Lucide アイコン (`<i data-lucide="icon-name"></i>`) に置き換える。
* **ファイルエンコーディング**: 日本語コメントや文字列の文字化けを防ぐため、全ファイル `UTF-8` で統一して書き出すこと。
